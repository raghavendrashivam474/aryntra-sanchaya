# Milestone v0.2.0 — First Vertical Slice

> **Status:** ✅ Complete
> **Version:** v0.2.0
> **Date:** 2026-08-04
> **Theme:** Prove the architecture end to end.

---

# Overview

The v0.1.0 milestone established the engineering foundation of Sanchaya.

The objective of v0.2.0 was to validate that the chosen Clean Architecture could support a complete, real-world feature from the user interface down to persistent storage.

Rather than implementing many features, this milestone focused on completing one feature end-to-end, ensuring that every architectural layer interacted correctly while maintaining clear separation of concerns.

The successful completion of this milestone demonstrates that the architecture is practical, maintainable, and ready for future expansion.

---

# Objective

Implement the first complete vertical slice of the application by allowing users to create and retrieve documents that persist across application restarts.

This milestone validates:

- Clean Architecture implementation
- Offline-first persistence
- Rust ↔ React communication
- SQLite integration
- Repository pattern
- End-to-end data flow

---

# Feature Delivered

## Document Management (Basic)

Users can now:

- Add a document with:
  - Title
  - Category
  - Issuer
  - Issue Date
  - Expiry Date
  - Description
- View all stored documents
- Identify expired documents visually
- Identify documents expiring within 90 days
- Persist documents between application launches

All functionality operates entirely offline.

No network connectivity is required.

# Data Persistence

Documents are stored locally using SQLite.

Database location:

```text
%APPDATA%\com.aryntra.sanchaya\sanchaya.db
```

Database characteristics:

- Automatically created on first launch
- Offline-first
- WAL mode enabled
- Foreign key enforcement enabled

Persistence has been verified by restarting the application and confirming previously created documents remain available.

# Out of Scope

The following features were intentionally excluded from this milestone:

- Editing documents
- UI delete functionality
- File attachments
- Search
- Filtering
- Sorting
- Dynamic categories
- Unit tests

These features belong to future milestones.

---

# Known Limitations

Current limitations include:

- Documents cannot be edited.
- Documents cannot be deleted from the user interface.
- Categories are duplicated in both Rust and TypeScript.
- Dates are stored as UTC midnight.
- Pagination is not implemented.
- All documents are loaded into memory.

These limitations are acceptable for the first vertical slice and are documented for future iterations.
