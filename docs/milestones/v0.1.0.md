# Key Architectural Decisions

## 1. Clean Architecture

The project adopts Clean Architecture to ensure long-term maintainability and independence from frameworks, databases, and user interfaces.

Business logic remains isolated from implementation details.

---

## 2. Standard Tauri Layout

Rather than restructuring the default Tauri project layout, Clean Architecture is implemented **inside the Tauri host**.

This preserves compatibility with:

- Official Tauri documentation
- Tauri CLI
- Community plugins
- Future contributors

while maintaining clear architectural boundaries.

---

## 3. Offline-First Design

Offline capability is a permanent architectural principle.

Core functionality must operate without internet connectivity.

Cloud synchronization, if introduced in the future, will remain an optional enhancement.

---

## 4. Privacy-First Design

User documents remain under user control.

The application is designed around local ownership of data rather than cloud dependency.

---

## 5. AI Deferred

Artificial Intelligence is intentionally excluded from the MVP.

Early versions rely on deterministic, rule-based workflows.

The architecture has been designed so AI can later be introduced as an Infrastructure concern without restructuring the existing system.
