# v0.5.0 Milestone Report — Search & Filter Documents

**Released:** 2026-08-09
**Previous release:** v0.4.0
**Tests:** 68 passing (backend unchanged)
**Status:** Complete

---

## Objective

Make an increasing number of documents easier to find without
changing the existing document lifecycle or architecture.

---

## What Was Built

### Search
- Case-insensitive text search across title, issuer, and description
- Whitespace trimmed before matching
- Empty query returns all documents
- Updates the visible list as the user types

### Category Filter
- Dropdown selector with All Categories default
- Filters by any of the eight DocumentCategory values
- Selecting All restores the full list

### Combined Filtering
- Search query and category filter compose correctly
- Both conditions must be satisfied simultaneously

### Empty States

| Situation | Message |
|---|---|
| Vault contains no documents | No documents yet. Add your first document. |
| Filters matched nothing | No matching documents. Try a different search or filter. |

### Document Count
- Unfiltered: `N documents`
- Filtered: `N of M documents`

### Clear Controls
- Clear button appears only when filters are active
- Resets both search and category simultaneously
- No backend operation required

---

## Architectural Decision

Filtering implemented entirely on the frontend as derived state
over the already-loaded document collection.

Rationale:
- All documents loaded into React state on startup via find_all()
- Dataset is small — personal offline desktop vault
- filteredDocuments computed via useMemo, not stored as mutable state
- Zero backend changes eliminates risk to existing 68-test suite
- No premature database infrastructure (FTS5, indexes, search rankings)
