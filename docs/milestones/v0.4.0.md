# Aryntra Sanchaya v0.4.0 - Delete Document

**Released:** 2026-08-09
**Previous Release:** v0.3.0
**Sprint Objective:** Complete the Document CRUD lifecycle by exposing
the existing repository deletion capability through the full
Application -> Presentation -> Frontend vertical slice.

---

## Summary

v0.3.0 proved that Sanchaya could safely update existing data without
damaging the architecture.

v0.4.0 proves that the architecture can safely handle a
**destructive operation** with explicit user confirmation, meaningful
error handling, and no optimistic UI updates.

The Infrastructure layer already supported deletion since v0.2.0.
This sprint exposed that capability through the missing upper layers.

---

## What Changed

### Application Layer
- Added delete_document::execute(id, repository) use case
- Verifies document exists before deletion (explicit intent, not silent)
- Returns SanchayaError::NotFound(id) for unknown IDs
- Propagates repository errors cleanly
- 7 new application-layer tests

### Presentation Layer
- Added delete_document Tauri command
- Registered in invoke_handler
- Follows the existing thin-command pattern (no SQL, no business logic)

### Frontend Service
- Added deleteDocument(id) to documentService.ts
- Consistent error handling with addDocument and updateDocument
- Only file allowed to call invoke - boundary preserved

### Frontend UI
- Added Delete button to each document card in DocumentList.tsx
- Inline red confirmation prevents accidental deletion
- Cancel dismisses confirmation without side effects
- Successful deletion removes document from local state
- Failed deletion leaves document visible and surfaces an error banner
- No optimistic removal - UI only updates after backend confirms

---

## Architecture

Dependency direction unchanged:

    React -> DocumentService -> Tauri Command
                                    |
                                    v
                               Application
                                    |
                                    v
                                  Domain
                                    |
                                    v
                          DocumentRepository (trait)
                                    |
                                    v
                           SqliteDocumentRepository
                                    |
                                    v
                                  SQLite

- Frontend does not know about SQLite
- Application does not know about SQLite
- Domain does not know about Tauri
- Infrastructure implements the repository contract

No architectural boundaries were crossed or weakened during this sprint.

- File attachment support
- Search or filter capability
- Cloud synchronization
- AI features
- New database or ORM abstraction
- New state-management framework
